# Phase 2 — independent Copilot CLI contract verification

**Verdict: VERIFIED WITH REQUIRED DESIGN CHANGES.** The model-facing `view`/`grep`/`glob` restriction is reproducible on Copilot CLI 1.0.91, but the Phase 1 launch is **not sufficient as written**: it permits automatic reads elsewhere in the system temp directory, and a profile hook or MCP server can execute outside the model tool surface while the manifest still says exactly three tools. The revised contract below is viable for a local desktop reviewer only if its pre-launch profile checks and post-run rejection rules are implemented and then retested against the product launch path. This verdict does not approve the original invocation or a prompt-only boundary.

**Environment and scope:** 2026-10-02; Windows 10.0.26300.0 x64; .NET 10.0.401; Copilot CLI 1.0.91 from the installed npm package; dedicated OAuth-authenticated `%LOCALAPPDATA%\AIReviewDesk\Copilot`; disposable Git fixtures and ephemeral run directories. The harness did not read or log credential values. Authenticated probes used the approved network-enabled context. No customer repository or WPF implementation was used. Current GitHub documentation was consulted, but these observed results are version-specific; CLI 1.0.91's hook behavior disagreed with the documented expectation for `disableAllHooks`.

## Independent observations

| Challenge | Evidence and conclusion |
|---|---|
| Original adversarial suite | All 13 Phase 1 cases were rerun. Completed runs had zero malformed JSONL lines and an effective manifest of exactly `glob`, `grep`, `view`. The create, modify, delete, PowerShell, empty Git commit, instruction, and selected agent/skill cases made no fixture or HEAD change and exposed no write, shell, or task execution event. The external read case executed all three allowed tools. This supports the **model tool** boundary, not the whole process boundary. |
| Repository content | `--add-dir` agent/skill and instructions did not widen the manifest. A valid repository hook and valid `.github/mcp.json` in the additional directory did not start from the separate app-owned cwd. A source-file injection probe did not obey its hostile instruction, but the model made the injection text part of its finding. Review content remains influenceable by untrusted source even when technical authority stays read-only. |
| Read scope | With Phase 1 flags, `view` read a synthetic sibling temp file by absolute path and `..` traversal. `--disallow-temp-dir` denied both paths and denied both a symbolic link and a Windows junction in the reviewed fixture pointing to a sibling directory; with that same flag, `glob`, `grep`, and `view` still read the explicitly added fixture. The link and junction were actually created in their respective runs. This is a necessary launch change, not proof of an OS-wide filesystem sandbox. |
| Profile hook | A synthetic `sessionStart` profile hook wrote a temp marker under the exact constrained invocation, while the manifest remained three tools. Setting `disableAllHooks=true` in profile `settings.json`, including through the CLI's interactive `/settings` command, did **not** prevent it in a fresh noninteractive run. The synthetic hook was removed afterward. The app must reject hook-bearing profile/run configuration before launch; the setting alone is not a safeguard on this version. |
| Profile MCP | A valid synthetic profile `mcp-config.json` caused its local server process to start and write a temp marker under `--disable-builtin-mcps` and the three-tool allowlist. The server then exited and was reported `failed`; it never appeared as an effective model tool. `--disable-mcp-server phase2-profile-synthetic` prevented startup and reported it `disabled`. The profile MCP files were removed afterward. Built-ins were reported disabled; a valid `.mcp.json` in the untrusted ephemeral cwd did not start in the tested arrangement. The manifest alone cannot prove MCP startup isolation. |
| Manifest timing and completion | `session.tools_updated` arrived early but its data contained only `model`, with no usable tool list. `session.usage_checkpoint` reported the three tools after the first `tool.execution_start` in read runs (for example 13,166 ms versus 11,606 ms). A cancelled run could have tool activity and no checkpoint or terminal `result`. Thus the application can validate and reject a completed result, but cannot use the current run's JSONL manifest as a before-execution gate. |
| Cancellation and repository change | Phase 2 cancellation stopped an active run with partial JSONL, no `result`, unchanged fixture, and one newly observed Copilot child no longer present after process-tree termination. The full rerun also ended its startup cancellation with no child remaining. An external actor's mid-review edit changed the fixture fingerprint while HEAD remained the same; the result must be stale and unusable for a clean handoff. |
| Transport and profile | A valid `{"findings": []}` response, Unicode/newline stdin, and the 24 KiB synthetic context case repeated. The persistent dedicated profile authenticated the runs without token environment variables or credential handling by the harness. A network-blocked startup earlier returned exit 1 with no JSONL; absence of a manifest/result must reject the run. |

## Required v0.1 design changes

1. Add `--disallow-temp-dir` to the fixed, noninteractive review invocation. Keep the cwd an empty app-owned run directory and the reviewed repository as the sole `--add-dir`. Do not expose resume, interactive shell aliases, workflows, arbitrary agents, or user-editable CLI flags in the review path. Treat CLI version/argument changes as a contract change requiring verification.
2. Before starting Copilot, validate the **entire executable configuration surface**, not just model tools. The dedicated app profile and run directory must be controlled and checked for hook files or inline hooks, MCP configuration, installed/enabled plugins, extensions, and other executable startup contributions. Reject unknown or changed configuration rather than merely setting `disableAllHooks` or trusting `--disable-builtin-mcps`. Keep `disableAllHooks=true` as defense in depth, but do not rely on it. Do not read, copy, export, or persist OAuth credential values. If a hook or MCP source cannot be inspected reliably, fail closed. The profile must not be shared with ordinary Copilot use.
3. Validate each completed run's exact tool set as `{view, grep, glob}`, expected disabled built-in MCP status, JSONL syntax, terminal `result`, process exit, and observed tool requests/executions. Any missing or extra capability, unexpected MCP server, malformed/partial stream, cancellation, or error rejects the review; never present unverified findings as trusted output. A separate no-source capability preflight tied to the CLI version/profile state may improve detection before review content is supplied, but it does not replace per-run validation or pre-launch configuration checks.
4. Compare deterministic repository fingerprints before and after every run. Any difference marks the result stale/unusable for clean handoff, even with a normal exit and plausible findings. Keep process-tree cancellation and transient raw event handling.
5. Treat read reach as a local-desktop trust assumption, not a security promise over arbitrary filesystem paths. The revised flag and tested path denials narrow the launch, but no exhaustive Windows path or external-actor audit was performed. Repository text is untrusted review data; structured findings still need independent ChatGPT/Codex assessment.

The present dedicated profile was left without the synthetic hook or MCP files; `settings.json` retains `disableAllHooks=true`. The app still needs to implement and test the pre-launch checks above. Product work may proceed with core/Git/Copilot integration slices, with these safeguards as acceptance criteria for the Copilot integration and release verification. No WPF work began in Phase 2.

## Verification and limits

`dotnet build` and harness `--self-test` passed. The full 13-case authenticated original suite, a nine-case initial Phase 2 suite, focused `--disallow-temp-dir` path/link/junction checks, profile hook positive/negative controls, profile/working-directory/repository MCP checks, and a JSONL event-shape check were run. Summary JSON was used locally and is not retained in the repository; Phase 1's report remains unchanged as historical evidence. These probes establish the stated behavior on this host and CLI version. They do not prove universal Copilot CLI security, prevent another same-user process from changing files or configuration during a run, or establish behavior after an update.
